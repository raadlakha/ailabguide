Step 01
User chats in. AI greets, understands, tries to help.
The Virtual Agent picks up the conversation. It already knows who the user is, what system they own — all from the Knowledge Graph. It tries to resolve the issue with a troubleshooting guide first.
Knowledge Graph means zero onboarding friction. Emphasise: the agent knows the user before they finish typing — no "what's your employee ID?" moments.
→
Step 02
Can't fix it in chat. User uploads a screenshot. AI reads it.
When the chat steps don't work, the user uploads their error screenshot. Document Intelligence automatically reads the image, extracts the error code (VX-3042), and populates it into the incident — no typing, no manual entry, no ambiguity.
Live demo moment: show the VX-3042 extraction happening. This lands well with ops-heavy audiences — "no manual entry" is a real pain point they recognise immediately.

Step 03
A specialist AI agent searches KB, analyses logs, builds a fix.
The Resolution Finder Agent kicks in. It optimises the search query, retrieves matching knowledge articles, analyses error logs, and if it finds a match — writes a structured resolution plan back to the incident. If not, it falls back to privacy-safe web search.
Now Assist Skill Kit is the SC differentiator — position it as a resolution engine, not a chatbot. The structured plan written back to the incident is what separates this from generic AI.
→
Step 04
Another agent executes the fix on the actual server. Done.
The Observability Agent sends the plan to Azure AI Foundry via A2A protocol. The external agent restarts the NetBackup job, verifies the backup completes, and reports back. ServiceNow closes the incident automatically — or hands it to L2 with a full execution log if something goes wrong.
The "wow" moment: the fix executes outside ServiceNow via A2A. Ask the audience — "how many of your incidents require touching a system outside ServiceNow?" — then show this closes that loop automatically.
